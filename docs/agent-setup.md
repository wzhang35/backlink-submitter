# Agent 接入指南

用于首次收到仓库链接、准备新项目或检查已有接入。先读 [通用 skill](../.agents/skills/backlink-submitter/SKILL.md) 了解执行边界；候选筛选和核验细节仍由 skill 及其 references 维护，本指南只负责接入。

目标是准备好处理候选所需的环境、产品资料和记录系统。仅收到仓库链接不代表获准安装软件、创建云资源、修改已有记录或提交网站；按用户当前请求和已有授权推进，已获授权的步骤不重复询问。资料、授权或验证确实缺失时再交给用户，继续完成不受影响的准备工作。

## 1. 定位工作区与检查能力

优先复用已有 checkout、项目配置和执行状态。需要下载工具时，将本仓库放在独立工作目录，不把真实项目配置、素材或记录提交进工具 Git。

| 检查项 | 如何判断 | 缺失时怎么做 |
|---|---|---|
| 本地文件和终端 | 能读取本仓库、运行命令、保存本机配置 | 说明宿主缺少的能力，不能只凭网页聊天声称接入完成 |
| Git、Node.js 18+ | 查看 `git --version`、`node --version` | 使用官方安装方式，遵守宿主的安装授权要求；本仓库无需安装 npm 运行依赖 |
| 飞书 CLI | 查看 `lark-cli --version`，读取当前命令帮助 | 按 [飞书官方 CLI 接入说明](https://github.com/larksuite/cli#installation--quick-start) 安装，不猜包名或复制第三方脚本 |
| 飞书 skills 和用户授权 | 能读取当前环境的 `lark-suite` 及对应 Base/文档能力，所选 profile 有资源访问权 | 按官方 CLI 指引安装配套 skills；依其认证规则让用户完成授权，复用已有配置，不擅自切账号或扩大权限 |
| 用户 Chrome | 能绑定确切标签页、读取公开 DOM/链接、保留人工交接现场 | 按 agent 宿主的浏览器接入说明处理；缺少 Chrome 能力时只完成其他准备，不以 HTTP 结果替代公开核验 |

飞书 CLI 及其 skills 不随本仓库分发。安装指令、认证步骤以官方当前说明和已加载的飞书 skill 为准；首次安装后可能需要重启 agent 才能加载 skills。本流程使用用户身份，Base 账号/profile 要与项目授权一致。

## 2. 收集产品资料

先读取用户已有产品文档、Submission Kit 和项目资源，核实官网与产品身份。只询问无法从已授权资料中获得、且影响当前步骤的内容；不凭邮箱推断任职或补造业务声明。

Submission Kit 是该项目可维护的在线提交资料文档，包含实际文案、账号标识和素材入口。已有 Kit 直接复用；没有时，先整理以下最小模板，按用户授权创建在其选定平台。本机 `kit.json` 只保存路由，不能代替这份文档。

```markdown
# 产品提交资料

## 产品

- 产品名称：
- 规范官网 URL：
- 一句话说明：
- 可核实的产品介绍／主要功能：

## 联系与账号

- 获准公开的联系信息：
- 指定登录账号／Google 邮箱（仅标识，不填密码）：
- 提交人：

## 素材与可选资料

- Logo、截图等素材的线上 URL／本地路径映射：
- 社交链接、视频、定价页等：

## 本项目记录

- 飞书 Base 表格／视图入口：
- 候选网址、清单或其维护入口：
```

先确认名称、官网和准确介绍。联系信息、登录账号和素材按具体站点需要补齐；可选项未知可留空，不要求用户提供与当前任务无关的资料。密码、验证码、API Key 和飞书凭证不能写入 Kit、工具源码或聊天。

## 3. 接入记录系统

先判断属于哪种情况，再按 [Base 标准与接入说明](../.agents/skills/backlink-submitter/references/base-setup.md) 操作：

| 项目情况 | 处理方式 |
|---|---|
| 没有 Base | 用户授权建表后，生成标准字段 JSON、设置项目经办人选项并创建空表；拿到实际路由后建立项目配置，再 `check-schema` → `init` → `bootstrap` |
| 已有空表，首次使用工具 | 检查字段，审阅并在授权范围内处理差异；项目持久目录从未创建时才可 `init` |
| 已用过本工具 | 恢复对应项目的原始持久状态及共享 circuit，再 `check-schema` 和 `bootstrap`；不要重新初始化 |
| 表中已有候选或历史，首次使用本工具 | 只读检查字段与记录，说明当前没有自动接管已有非空表的命令；提出保留历史与防重复提交的迁移方案，待审阅后处理 |
| 状态缺失、损坏或来源不明确 | 报告具体问题并审阅恢复；不能删目录、清空表格或创建空 ledger 来绕过检查 |

创建／修改远端表格按用户授权执行；不要把“完成接入”扩大成覆盖已有业务结果。刚建空表时先初始化本机状态，再按授权导入候选，不能先导入非空记录再调用 `init`。

本机路由参考 [虚构配置](../projects/example/kit.json)，实际文件放在 `projects/<project-id>/kit.json`。`project-id` 使用小写字母、数字和连字符，并与配置的 `id` 一致；Base URL、baseToken、tableId/viewId 必须属于同一目标，不能猜 ID。profile、defaultSubmitter 及可选的 sourceProjectRoot 只按当前项目填写。

还没有真实表 ID 时，可按 Base 指南用 `example schema` 生成字段定义；该命令不访问远端。先将输出中的 Submitter 示例选项替换为已确认的项目经办人，再用于建表。其他命令必须使用该项目的真实配置，不要用示例路由操作云资源。

## 4. 检查就绪状态并交接

不需要另建“接入成功”文档。在聊天中简短汇报：

- 环境、飞书账号/profile 和 Chrome 是否可用。
- 产品 Kit、目标 Base 和本机项目路由是否一致。
- 表字段、原始持久状态是否通过检查；已有历史是否仍待迁移。
- 候选从哪里取得，以及尚缺什么、需要用户完成的单一动作。

只有相应检查真实通过，才说明可开始提交或核验；“资料已整理但缺浏览器”“已有表待迁移”等必须如实区分。接入完成后按用户请求决定下一步：只要求接入就到此；已明确授权处理候选时继续既定范围，不重复索取相同授权。
